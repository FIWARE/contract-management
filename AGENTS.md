# Contract Management

## Overview
A Micronaut-based service that manages contracts in a FIWARE IAM ecosystem. It integrates with TM Forum APIs (product ordering, catalog, agreements, quotes), supports OID4VP (OpenID for Verifiable Presentations) authentication, and connects to a DSP (Dataspace Protocol) Rainbow adapter.

## Tech Stack
- Language: Java 21
- Build: Maven (parent: Micronaut Platform 4.7.1)
- Framework: Micronaut 4.7.1
- Crypto: BouncyCastle 1.81 (`bcprov-jdk18on`, `bcpkix-jdk18on`), Nimbus JOSE JWT 10.5
- OID4VP: `io.github.wistefan:oid4vp-client-lib:0.0.5`
- Code Generation: Lombok 1.18.36, MapStruct 1.5.3, OpenAPI Generator
- Test: JUnit 5, Mockito, Awaitility, Unirest

## Key Conventions
- Configuration classes use Micronaut `@ConfigurationProperties` with nested records
- Records use `@Introspected` for Micronaut bean introspection
- Nullable fields annotated with `@Nullable` from `io.micronaut.core.annotation`
- Factory pattern (`@Factory` + `@Bean`/`@Singleton`) for complex bean creation
- Conditional beans via `@Requires(bean = ...)` and custom `Condition` implementations
- Lombok `@Data` for mutable configuration classes, Java records for immutable config
- OpenAPI-first: specs in `api/` are generated by `openapi-generator-maven-plugin` executions in `pom.xml`
  (`generatorName` micronaut, `modelNameSuffix` VO, `supportAsync` -> `Mono` returns); controllers implement the generated `*Api`
- Controllers: `@Controller("${general.basepath:/}")`, guarded by `@Requires(condition = ...)`; Lombok `@RequiredArgsConstructor` + `@Slf4j`
- Handler registries: `List<XxxHandler>` injected, dispatch via `isEventTypeSupported` (see `NotificationListener` / `TMForumEventHandler`)
- Unit tests use Mockito mocks and JUnit 5 `@ParameterizedTest` + `@MethodSource`; integration tests use k3s (k3s-maven-plugin)
- Management endpoints (micronaut-management) listen on port 9090 (cluster-internal, unauthenticated; `/refresh` lives there)
- Outbound authenticated calls: set `Oid4VpAuthHandler.CLIENT_ID_ATTRIBUTE`/`SCOPE_ATTRIBUTE` (a `Set`) on the request and
  call `Optional<AuthHandler>.executeWithAuth` (see `ContractManagementAdapter`); a 401 triggers one OID4VP token fetch + retry
- Metrics: inject `Optional<MeterRegistry>`, fall back to `CompositeMeterRegistry` (see `EventListener`); bounded tag values
- Doc-comment density is low: one-line Javadoc on classes/interfaces and interface methods, Javadoc on configuration
  fields; most implementation methods have none. Match that — do not add `@param`/`@return` blocks
- Logging: failures are raised as `ContractManagementException` subclasses with a `FailureReason` code and the ids involved,
  keeping the cause; they are logged once (per failing order handler in `ProductOrderEventHandler`, or in `CatchAllExceptionHandler`),
  never log-and-rethrow. At that single point log `DownstreamError.reason(e)` (adds the downstream status/body, which the
  stacktrace lacks) and attach the exception. Lines about an order start with
  `Order <id>:`. Whole policies/orders only at DEBUG. Output format via `LOG_FORMAT=TEXT|JSON` (see README)
